# Git Branch 设计文档

本文记录详细交互、Git 操作边界、技术方案和验收记录。面向使用者的功能和入门步骤见[插件说明](../README.md)。

> `2.0.0` 支持跟随 VS Code 显示语言。扩展标识为 `hkllyx.git-branch`。

**工作区改动在左侧原生 Changes，分支管理在左侧「分支 / Branches」，提交和历史文件在底部 Git 历史。** 借鉴 IntelliJ IDEA 的分支、提交图和文件变化联动，不搬进一套独立的提交界面。

## 运行环境与界面语言

- 扩展自动读取 **VS Code 的显示语言**，不是操作系统、Git 或当前文件的语言。命令面板中运行 **Configure Display Language（配置显示语言）**，选择所需语言（如果未安装则先安装对应语言包），然后按 VS Code 的提示重启。不需要单独设置扩展的语言。
- **简体中文**（`zh-cn`）显示「分支」「Git 历史」；**繁體中文**（`zh-tw`）显示「分支」「Git 歷程記錄」；**英文**显示 **Branches** 和 **Git History**。其他显示语言（例如日语）下只有本扩展回退到英文，不改变 VS Code 本身的显示语言。
- 分支视图、菜单、分支操作的确认和结果提示、提交图、文件与详情区均随显示语言切换。提交时间按本地时区显示：日期列为 `yyyy/MM/dd HH:mm`，提交悬浮与详情为 `yyyy-MM-dd HH:mm:ss`，格式不随语言变化。分支名、标签名、作者、提交说明和文件路径不翻译；Git 或远端返回的原始诊断在脱敏后作为详情显示。原生 Changes 仍由 VS Code 自己翻译。

扩展清单要求 VS Code `^1.85.0`；该范围不是完整的兼容性测试结论，已验证环境见文末。不是 Git 仓库、内置 Git 未启用、受限模式和虚拟工作区均不属于可正常使用的场景。安装运行不需要额外装 Node；从源码测试或打包才需要。

后续交互变更按[工程约定](../AGENTS.md)同步更新本文。本文不含截图。

## 1. 工作台布局

下文以简体中文和英文标签举例。分支树的 `Local / Remote / Tags` 分别对应简体中文的「本地 / 远程 / 标签」和繁體中文的「本機 / 遠端 / 標籤」；布局与操作规则不随语言改变。

- **Source Control → Changes**：继续由 VS Code 内置 Git 提供。暂存、取消暂存、提交、冲突解决和工作区 Diff 均沿用原生入口。插件不另建提交框，也不注册第二个 Git 源代码管理提供者。
- **Source Control → Branches**：增加一个与 Changes 同级的原生树视图。它只列当前仓库的引用和分支操作，不在树内展开提交、文件或对比会话。
- **底部 Panel → Git 历史**：独立于 Terminal、Output 等标签。宽屏下左侧是提交图，右侧是文件和可折叠的单提交详情，两侧独立滚动，中间可拖拽调宽。窄面板改为「提交图 / 文件 / 详情」切换，多选时隐藏「详情」。面板内不重复放分支树，文件 Diff 打开在主编辑区。容器使用内置 `history` 图标；Webview 的刷新、引用和警告使用 VS Code 自带 Codicon 字体中的 `refresh`、`tag` 和 `warning`。提交拓扑图仍按历史数据绘制。
- 布局顺序以本文描述为准，不要求 VS Code 固定视图顺序，不改变用户已移动或隐藏的视图，也不替换 VS Code 自带的 Source Control Graph。

当前支持分支创建、检出、更新、推送、合并、变基、工作树创建和分支删除，并可比较两个分支或将分支与当前工作树比较。底栏支持提交与文件右键操作，以及多选提交的合成差异。暂不做自定义快捷键、远程分支重命名、强制推送、标签删除或跨仓库对比。

## 2. 左侧 Branches

### 扁平列表与标签显示

- 列表顶部是无图标的 `HEAD (Current Branch)`，双击查看当前 HEAD 的历史。分离 HEAD 时仍改为 `HEAD (Detached)`，附短哈希；仓库尚无提交时显示「尚无提交」。`Local` 中的当前分支使用内置 `star-full`，平时采用主题的 `charts.yellow`，选中后由 VS Code 决定颜色，不强制保色。其余分支使用内置 `git-branch`，标签使用内置 `tag`。
- `Local` 和 `Remote` **只是固定类型区段，不是可配置的分组**。默认展开，内部只放一层分支条目；`feature/20261210/search-index` 是一行，斜杠不拆目录。远程完整显示 `origin/main`、`origin/feature/20261210/search-index`、`upstream/main`，它们直接并列在 `Remote` 下，**不增加 `origin`、`upstream` 中间层**。`origin/HEAD` 等符号别名不作为可操作分支显示。
- 当前本地分支置顶，其余本地分支、远程分支各按显示全名稳定排序。相同尾名的多个远程分支以完整前缀区分。长名称可截断，但悬停及操作确认均显示全名。没有收藏分组或按前缀分组模式。
- `Branches` 标题栏 `…` 提供「显示标签／隐藏标签」，**默认关闭**，按工作区记住设置。开启后读取当前仓库的标签，再在末尾追加扁平的 `Tags` 区段，在历史范围选择器列出可查看的标签，并在提交图显示 Git 标签徽标。若开启后立即打开范围选择器，等待这次刷新，不展示旧快照。关闭时三个位置均隐藏 Git 标签，但保留分支徽标，既不删除标签也不改变普通历史范围。若正在查看某个标签，再关闭时回到当前 HEAD 历史。左侧标签只提供查看历史；新建标签从提交右键发起，开关不影响创建。附注标签解析到其指向的提交，不指向提交的标签不提供历史入口。
- 本地分支行的 `↑`／`↓` 是该分支相对**自己配置的上游**领先／落后的提交数。比如 `topic` 跟踪 `mirror/trunk` 时，只比较 `topic` 和本地的 `mirror/trunk`，不使用当前分支的上游，也不按同名猜成 `origin/topic`。切换检出不改变比较对象。没有上游、缺少本地上游引用或没有差异时不显示计数。普通「刷新」只重新读取本地 Git 状态，不联网；要看到服务器上的新提交，须先 Fetch。

### 仓库与操作入口

- 同一窗口可打开多个仓库，但 Branches 和底栏一次展示同一个仓库。优先恢复仍可用的手动选择；否则默认选择**仓库根目录与工作区文件夹根目录一致**的主仓库。有多个主仓库时，按 VS Code 工作区文件夹顺序选择第一个，不按 Git 发现顺序，也不让嵌套仓库抢占主仓库。后续发现优先级更高的主仓库时，只更新默认选择，不覆盖手动选择。
- 没有匹配的主仓库时，只有一个已打开的仓库就自动选中；有多个则提示手动选择。打开多个仓库时 `Branches` 标题旁显示活动仓库名，标题栏的原生仓库图标打开仓库选择器；只有一个仓库时隐藏该图标。原生 `TreeView` 的标题描述只是文本，不能像内置 Changes 的分支文字一样绑定命令，因此使用标题栏图标，不在 `…` 中重复提供「选择仓库」。也可从底栏切换，两个视图同步更新，手动选择按工作区记住。重名仓库在选择器中附路径；不加仓库树层，不跟随编辑器文件切换，不触发 Git 检出。
- 标题栏保留刷新，不再提供单独的查找和创建入口。按引用名或短哈希查找可在底栏历史范围选择器完成；建分支仍可从分支右键或提交右键发起。命令面板中的检出、推送源分支和分支对比均复用同一个原生引用选择器：分隔线和图标一致，行末只显示短哈希。推送源分支只列本地分支，检出和分支对比可选本地与远程分支。不把选仓库或选推送目的远程混入分支选择器。
- 单击分支只选中，不打开历史；双击或右键「查看历史」才切换底栏范围，**不检出**。VS Code 的原生树不给扩展鼠标点击次数：用户已启用 `workbench.list.openMode: doubleClick` 时直接沿用原生双击；默认模式下用约 500 ms 内同一项连续激活识别双击，不修改用户的设置。

## 3. 分支操作

### 何时需要确认

- **常规操作不弹二次确认**：检出本地分支、远程分支或指定提交，创建、重命名、推送、普通合并、快进更新和新建工作树，直接执行或在用户完成必要输入后执行。分支名、推送目的地、工作树路径等依然要明确，不是自动猜测。创建通知上的 `Checkout` 是可选的后续操作，不是创建确认。
- **高风险操作只确认一次**：删除本地／服务器分支、`Undo Commit`、`Drop Commit`、`Squash Into`，以及真正要重放提交的变基。`Reset` 选择模式即为确认，编辑提交说明以表单上的「改写提交」为确认。`Update` 仅在必须临时保存跟踪文件时询问是否 Stash，快进不另弹确认。
- 确认中会显示仓库和具体目标。有没有弹窗都不改变安全检查：按操作复核引用、上游、HEAD 和工作区；参数过期就提示重试，不绕过 Git 锁、worktree 限制或远端保护。

### 创建与检出

- **创建分支**：右键 `Create Branch` 直接采用被右键的分支作起点，不再打开起点选择器。输入框标题显示来源分支及短哈希；输入框原样填入完整来源名（如 `feature/search` 或 `origin/feature/search`），不加后缀，光标停在末尾。已存在的本地分支名、与本地分支的引用路径冲突或不合法的名称会显示错误提示（默认主题中为红框），阻止创建。输入有效名称后回车即可创建，真正写入前再次检查。创建不继承上游、不自动切换；成功通知上提供 `Checkout`，点击后直接检出。忽略通知或检出失败均保留新建分支。
- **检出本地分支**：目标是明确的本地分支；已在目标上则提示无需切换。允许 Git 在安全时保留已有改动；会覆盖已跟踪、未跟踪或被忽略文件时拒绝。不强制切换、不自动暂存。仓库有未解决冲突、正在合并或变基，或目标已在其他 worktree 检出时，提示原因并退出。
- **检出远程分支**：不弹命名框或确认框。只从所选条目的显示名开头去掉该远程的前缀，例如 `origin/feature/search` → `feature/search`，其余路径原样保留；自定义 fetch refspec 没有匹配前缀时保留完整显示名。直接创建本地跟踪分支、设置上游并检出。本地同名（即使已跟踪对应远程分支）或路径冲突时直接失败，不切换、不改已有分支；若只是要切到已有分支，请从 `Local` 选择它。映射不唯一或不对应真实的 `refs/heads/*` 时不猜测。
- 尚无提交时不允许从空 HEAD 创建有起点的分支；提示先完成首次提交，不限定使用哪种 Git 工具。分离 HEAD 可以从当前 OID 创建新分支，但不对它执行拉取或推送。会修改工作区的操作遇到相关未保存编辑器时提示先处理，不替用户保存或关闭文件。

### 重命名与删除

- **重命名**预填原名，有效的新名称回车后执行非强制 `git branch -m`，保留原 tip、Git 分支配置和上游关系。可重命名当前工作树正在检出的分支，不切换文件内容；若分支在其他 worktree 使用，则提示先在该工作树切换。重名或路径冲突不覆盖。
- **删除本地分支**：只在其他本地分支显示。确认后执行 `git branch -d`；Git 要求分支已完全合入上游，没有上游时须已合入 HEAD。当前或其他工作树正在检出的分支不会删除；不会影响服务器分支。
- **删除服务器分支**：右键 `Remote` 条目选择 `Delete…`。确认框显示仓库、远程名称、由 fetch refspec 映射出的 `refs/heads/...` 和期望提交，并说明这不是清除本地缓存。确认后向该远程发送单一分支删除请求；成功后刷新分支列表，不删除同名本地分支，也不重写它的上游配置。
- **删除保护**：如果服务器分支不再指向确认时的提交，请先获取远程状态、核对后重新确认。尊重服务器权限与分支保护，不重试、不无条件强制。远程删除是否允许由服务器决定，不套用本地 `git branch -d` 的合并检查。拒绝歧义 fetch 映射、镜像、多个推送地址和获取／推送地址不同的远程。远程为本地路径时还需验证它不指向同一个 Git 仓库或其关联工作树。网络中断等导致结果不明时，先核对服务器状态。

### 快进更新与检出后更新

1. **更新（Update）**使用所选本地分支配置的远程上游；从命令面板运行则使用当前分支。无有效上游时停止。只获取该上游分支、更新对应远程跟踪引用并固定本次获取的 OID；不顺带抓取标签、清理引用或递归获取子模块。已包含上游时报告无需更新；已经分叉时提示不能快进，不自动合并或变基。
2. **当前分支**：获取前后复核 HEAD、上游和工作区。相关编辑器未保存、有 Git 操作进行中或存在冲突时停止。能快进时，非重叠的未暂存改动可原地保留；存在暂存改动，或未暂存的已跟踪改动与上游路径重叠时，先询问是否将已跟踪改动保存到具名 Stash。拒绝则不移动分支、不修改本地改动。未跟踪或忽略文件不挪走；可能被覆盖或占用保存改动的路径时拒绝。子模块有本地改动或存在 `git add -N` 的路径时，请先处理再快进。
3. **恢复改动**：快进后按该 Stash 的 OID 执行 `apply --index` 恢复原暂存状态；快进被阻止而仍安全停在原分支时也尝试恢复。恢复发生冲突时分别报告「分支是否更新」和「改动是否恢复」，不自动回滚或覆盖。即使恢复成功也保留 `Git Branch Update …` 恢复副本，确认无误后可手动清理。即使没有快进，已获取的远程跟踪引用仍可能更新。
4. **其他本地分支**：不切换、不修改当前工作树与索引，不 Stash。目标分支在其他 worktree 被检出时，提示到该处更新或先在那里切换分支。
5. **检出并更新（Checkout and Update）**：先验证所选本地分支及其上游，再直接检出，并按当前分支的快进规则更新。检出成功但更新失败时留在已检出的分支，提示失败原因，不切回原分支。

### 合并、变基与拉取到当前分支

- `Merge into Current` 和 `Rebase Current onto Selected` 使用所选引用的本地快照，不先 fetch。`Pull into Current Using Merge` 和 `Pull into Current Using Rebase` 只在远程条目显示：联网获取所选服务器分支的提交，再整合进**当前本地分支**。二者均不检出来源分支、不修改当前分支上游。
- 需有已检出的本地分支、可用的共同祖先，且没有未保存编辑器、冲突、其他 Git 操作或已跟踪改动。不会自动 Stash；未跟踪／忽略文件存在覆盖风险时停止。合并可快进或创建合并提交，均不弹确认。变基若能直接快进也不弹窗；只有需要重放当前分支提交时，才用实际目标 OID 确认一次。取消联网变基不会移动当前分支，但已获取的引用可能更新。
- 出现冲突时保留 Git 原生合并／变基状态，可在原生 Source Control 解决文件冲突，再用对应的 `git merge --continue` / `git rebase --continue` 继续，或用 `--abort` 取消。拉取已获取但整合未完成时，会分别提示。

### 新建工作树

- 未在其他工作树检出的本地分支可直接用于新的工作树。所选本地分支已检出时，提示从其提交创建新分支，不允许强制重复检出。远程分支从本地缓存的提交创建本地分支，成功后设置对应上游，不自动获取。
- 路径输入框完成后直接执行。目录须为绝对路径，父目录已存在，目标是 Git 元数据目录之外的新目录或空目录。保留原工作树的分支和本地改动，不自动打开新窗口；可用 VS Code 单独打开新目录。若工作树创建成功但设置上游失败，保留工作树并提示。

### 推送本地分支

- 可推送已选本地分支，不必先检出。已配置有效远程上游时，把它列为首选并预填远端目标名；没有上游时先选远程和目标分支名。目标输入显示来源和远程；新目标能明确映射到远程跟踪引用时，可选「仅推送」或「推送并设为上游」。完成这些选择后即推送，不再弹确认，只推送提交，不推送工作区改动。执行前复核源分支与远程目标，变化时提示重新发起。
- 只推送一个明确的 `refs/heads/*` 目标，不强推、不推标签和子模块。不支持镜像远程或配置了多个推送地址的远程，避免推到额外目标。非快进或保护规则拒绝时报告 Git 的原因，可提示先对比或拉取，但不自动重试或强推。若用户选择设置上游，则在推送成功后作为独立步骤执行；设置失败时报告部分成功，不再次推送。
- 沿用当前运行环境的 Git 凭据机制，不采集密码。需要交互而当前无法认证时可打开相应仓库的终端供用户处理。若网络中断导致写入结果不确定，提示先核对远端状态，而不是显示「一定失败」或自动重试。

## 4. 底部 Git 历史

### 提交图与单提交

- 工具栏依次提供当前仓库、历史范围、统一筛选框和刷新。初次打开和切换仓库时默认查看当前分支；范围按钮显示分支名，分离 HEAD 时显示 `HEAD`。此范围随检出变化，范围菜单可选 `HEAD` 返回跟随模式。手动选择具体分支或 `全部分支` 后不会因检出而改变范围。`全部分支` 遍历本地分支、缓存的远程跟踪分支及可解析的 HEAD，不加入仅由标签可达的历史。切换历史范围不检出、不改变工作区。
- 「选择历史范围」与分支对比、检出和推送源分支共用原生 Quick Pick。只有历史范围在顶部列 `HEAD` 和「全部分支」，并在启用「显示标签」后追加 `Tags` 分隔和指向提交的标签；分支候选使用 `Local`、`Remote` 原生分隔线，不显示空区段。各引用按名称或短哈希搜索，行末只显示短哈希；当前分支用原生 `star-full` 标记，不再附加 `Current Branch`。其他本地、远程分支用 `git-branch`，标签用 `tag`。跟随 HEAD 时默认高亮当前本地分支，分离时高亮 `HEAD`；已手动选定范围时高亮该范围，当前分支仍有星标。高亮只移动焦点，确认前不应用范围。
- 筛选框随 VS Code 主题，输入同一段文字即可匹配提交消息（标题或正文）、作者姓名或哈希前缀，不区分大小写。`Enter` 立即生效、`Esc` 清空，输入停顿约 220 ms 自动查询。筛选会重置日志并从头扫描，结果为空时明确提示；续页保留未读取的匹配项。
- 提交按拓扑顺序呈现，不按日期猜父子关系。虚拟滚动中的行共享同一套 CSS Grid 列，图、主题和已开启的列固定在同一行。可选列按 **作者 → 短哈希 → 时间** 排列；默认仅作者和时间，列偏好保存在当前工作区，更新不覆盖用户已选的列。标题栏的「显示列…」在图标字体可用时显示内置 `ellipsis` 图标，否则回退为文字。列间距缩为约一个空格，作者靠右以缩短与后续列的距离。关闭的列不占空间，窄面板中较长内容可截断但不换行。有引用的提交在主题后、元数据列前统一显示一个无边框 `tag` 徽标，不区分单个或多个。空间不足时优先截断主题，不挤占元数据列。全部引用名称仍只在徽标悬浮中显示；内置字体不可用时统一使用系统标签符号，不显示文字。行悬浮固定两行：第一行为提交标题，第二行为 `作者  ·  短哈希  ·  时间`，短哈希为 8 位，不显示相对时间。悬浮和详情用 `yyyy-MM-dd HH:mm:ss`；日期列仍用 `yyyy/MM/dd HH:mm`。时间基准是提交者时间，不是作者时间。完整哈希仍可从详情或复制命令获得。分叉及合并按真实父提交连线，父提交不在本地历史时用虚线标记。最多绘制 14 条泳道，超过时保留提交行并标 `⋯`。
- 单击提交，右侧展示文件和提交详情（完整信息、作者、时间、完整 OID、父提交）。普通提交对比父提交，根提交对比空树。**合并提交顶部只列合并结果相对每个父提交均有变化的文件**，没有时显示「无合并冲突相关变动」。这是从快照推断，不是历史冲突清单：自动合并的双侧改动也可能显示，完全取某个父版本的冲突可能不显示。双击顶部文件打开第一父提交与合并结果的两方 Diff。
- 单选合并提交时，下方显示 IDEA 的 `Changes to <短哈希> <父提交标题>` 折叠组。它们按实际父提交排列，不取当前分支名，也不限于冲突文件。各组分别展示**该父提交 → 合并结果**的完整差异，双击文件使用对应父提交作为左侧。空组不显示；顶部没有冲突相关文件时仍显示非空父组。每组独立展开、分页，支持列表／目录树。多选时仅将顶部的合并差异参与按文件合成，不显示父组。父对象缺失时显示读取错误，不当作空树或无冲突，也不自动联网补历史。
- 文件条目区分新增、修改、删除、重命名等状态。**单击文件只选中**（可配合 `Ctrl` / `Cmd` 与 `Shift` 多选），**双击才打开原生 Diff**；左侧旧版本、右侧新版本，新增／删除用空侧，重命名用旧路径和新路径分别读取。二进制、过大文件、子模块指针显示状态或对象信息，不强行当文本展示。历史提交和分支快照的内容取自 Git 对象，不读同名工作区文件。

### 提交右键菜单

右键直接打开 VS Code 原生操作菜单，替换提交行上的默认剪切／复制／粘贴。右键点已选中的行时，以当前选集为目标；右键点未选中的行时只操作该行，不修改已有选集。单选菜单如下；多选只开放复制哈希、Cherry-Pick 和 Revert。当前分支、父提交和保护条件不满足时，相应项置灰或在执行前说明原因。

| 菜单                               | 行为                                                                                                                                                                                         |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Copy Revision Number`           | 复制完整哈希，多选时每个哈希单独一行。                                                                                                                                                       |
| `Cherry-Pick`                    | 按旧到新的拓扑顺序，将当前分支尚未包含的选中提交拣选进当前分支。                                                                                                                             |
| `Checkout Revision`              | 直接检出所选提交，进入 detached HEAD，不移动分支引用。                                                                                                                                       |
| `Compare with Local`             | 左侧是所选提交快照，右侧是当前工作树中已保存的文件，不检出。                                                                                                                                 |
| `Reset Current Branch to Here…` | 选择 `Soft`（仅移动分支）、`Mixed`（同时重置暂存区）、`Keep`（保留不冲突的本地改动）或 `Hard`（重置已跟踪文件）。选择模式后执行；`Hard` 会明确提示丢弃改动，不自动清除未跟踪文件。 |
| `Revert Commit`                  | 按新到旧的拓扑顺序，为当前分支已包含的选中提交生成反向提交，不移除原历史。                                                                                                                   |
| `Undo Commit…`                  | 仅可撤销有父提交的当前分支 tip；移动分支到父提交，保留暂存区和工作树。只有原生 SCM 提交框为空时才回填原说明。                                                                                |
| `Edit Commit Message…`          | 带入原说明，在多行表单编辑；只改说明，不带入已暂存改动。                                                                                                                                     |
| `Squash Into…`                  | **把当前暂存改动合入所选提交**，保留目标说明；不是把多条已存在的提交压缩成一条。合入较早提交时要求没有未暂存的跟踪改动，保留具名 Stash 恢复副本。                                      |
| `Drop Commit`                    | 从当前分支的线性历史丢弃所选提交及其改动，保留并重放后续提交。不可丢弃根提交。                                                                                                               |
| `New Branch…`                   | 以所选提交为起点创建分支，成功通知可选 `Checkout`。                                                                                                                                        |
| `New Tag…`                      | 在所选提交新建本地轻量标签，不覆盖同名项、不自动推送。                                                                                                                                       |

- `Undo`、编辑说明、`Squash` 和 `Drop` 不改写本地远程跟踪引用已包含的提交。较早提交只支持改写当前分支的线性片段，不移动其他分支。根提交的编辑或 Squash 不要求父提交；含合并提交的目标或后续重放区间会被拒绝。
- 提交级 `Cherry-Pick`／`Revert` 要求已在本地分支、跟踪文件干净，且不自动选择合并提交的主父。遇到冲突保留 Git 原生状态，可在 Source Control 解决后执行相应的 `git cherry-pick --continue`、`git revert --continue` 或 `git rebase --continue`；也可用 `--abort` 取消，不自动覆盖文件。

### 多选提交查看合成差异

- 普通单击只选中该提交；`Ctrl` / `Cmd` + 单击增减选择；`Shift` + 单击从上一次普通或加减选择的锚点按已加载列表顺序选连续区间；加上 `Ctrl` / `Cmd` 则把区间加入已有选集。多选时不加载显示某一个提交的详情，宽视图隐藏详情区、窄视图隐藏「详情」入口。取消最后一个选择时不自动回落到其他提交。
- **按文件合成，而不是并列逐提交 Diff，也不是比较整个提交区间的快照。** 只取所选提交涉及的文件。对于能连接的文件变化，左侧用该文件第一次选中变更之前的版本，右侧用最后一次选中变更之后的版本；可合并连续的重命名，增删抵消或净内容与路径和文件模式未变时不列出。
- 跳选时只由未选提交引入的文件不出现。例如只选 `a1109bf` 和 `c311f24`，两次修改 `src/api/client.ts` 会合成一份 Diff；未选的 `b220d65` 独有的 `src/debug.ts` 不出现。合成规则与 IntelliJ 一致：**纯按文件路径首尾拼接**，不看提交是否同属一条祖先链，因此分叉的选集也能给出端点净差异，不再出现「无法合并差异」。如果中间未选提交也改变了 `client.ts`（包括两条分叉都在改），文件行只显示黄色警告图标，悬停说明「含未选提交的改动」：可看端点净差异，但不能一键应用。文件行不再显示打开箭头，直接点击即可查看 Diff。分叉端点之间的差异按所选提交的先后顺序拼接，可能与逐提交阅读的直觉不同，需要精确结果时请缩小选集。
- 焦点在提交列表时，`Ctrl+A`（macOS 为 `Cmd+A`）选中当前筛选范围内已加载的全部提交，包括滚动区外的行；不自动加载后续页，也不把新页加入现有选集。`Esc` 清除此列表的选择，保留键盘焦点。输入筛选条件、编辑提交说明时保留原生文字全选。
- 换仓库或范围清空；提交图重建时仅恢复新首屏仍可见的选择。使用点击增选或范围选择时最多选 50 个，超限保留原选集；键盘全选可以超过 50 个，但此时只保留行高亮和复制哈希，不自动计算合成差异，也不批量修改提交。缩小选集后可恢复差异。正常加载显示进度；个别提交失败时标明不完整并可重试。文件非常多时可用「显示更多文件」。

### 文件布局与右键菜单

- 文件区标题旁提供 `View as Tree` / `View as List`，在图标字体可用时显示对应的 `list-tree` / `list-flat` 图标，否则回退为文字。默认列表突出文件名，后面以灰色小字显示仓库相对目录（不重复文件名）；根目录文件没有目录后缀。树视图按目录折叠，文件行只显示文件名。重命名／复制的完整旧、新路径仍在悬浮中。按工作区记住显示方式，提交文件、合并父组、分支快照和工作树对比共用。切换布局不重新计算差异。
- 焦点在变动文件列表时，`Ctrl+A` / `Cmd+A` 全选当前标签页的文件，包括折叠目录、合并父组和「显示更多文件」后的条目。`Esc` 只清除该文件选集，保留提交选择。全选不打开 Diff，也不受批量应用的 200 文件上限限制；超过上限或跨合并父组时不可批量应用。
- **`Select`**（右键第一项）：把文件选集设为右键所在文件，取消此前的多选。用于只想针对单个文件继续操作时。
- **`Edit Source`**：打开当前工作树中对应的真实文件，可直接编辑。重命名优先使用新路径；工作树没有这个普通文件时不创建、不跳到外部路径。
- **`Open Repository Version`**：只读打开所选差异的仓库版本。提交或两分支快照比较取新侧（目标版本）；与工作树比较始终取仓库快照侧，不因交换方向而打开本地文件。仓库侧没有该文件时不可用；内容仍遵守历史对象的文本大小与类型限制。
- **`Cherry-Pick Selected Changes`**：按文件应用补丁，不执行提交级 cherry-pick。用 `Ctrl` / `Cmd` 增减文件，或 `Shift` 选择一段，右键任一已选文件可一次应用选集（最多 200 个文件）；右键未选文件只应用该文件。单击只选中，双击才打开 Diff。应用后只改工作树，**不暂存、不提交、不移动 HEAD**，可到原生 Changes 检查。
- 只能应用能生成安全补丁的历史或分支快照文件。查看合并提交时，批量应用限于同一对比组，不混用顶部列表与父组或不同父组的变动。工作树差异、冲突／类型变更、子模块、符号链接，以及间断、不完整或无法合成的多选结果不允许应用。普通预检不通过时整批不落盘；有外部进程并发或磁盘异常时不保证跨进程原子性，也不擅自回滚用户已有改动。

### 分支对比

- 「与当前分支对比」以仓库当前本地分支为**基准 A**，右键分支为**目标 B**。「与其他分支对比…」以右键分支为**基准 A**，选择器只选**目标 B**，不列出 A 本身。标题栏或命令面板的「分支对比…」也可直接指定 A、B。分离 HEAD 时使用后两种方式。两边可选同一仓库内的本地分支或远程跟踪分支；确定后解析并固定各自的 OID，不检出、不联网。
- 底栏显示 `基准 A → 目标 B`，其后紧接三个图标按钮：**刷新**（`refresh`，重新读取引用并固定两端）、**交换**（`arrow-swap`）和**退出**（`close`）。左栏显示 `A...B` 的可达性差集。分组标题为「分支名 独有」（英文为 `<branch> only`，繁體中文为「分支名 獨有」），文字与折叠箭头使用对应方向徽标的描边色。标题加大字号；分支名过长时只截断分支名，始终保留后缀，悬浮显示完整标题。点击标题或按 `Enter` / `Space` 独立折叠／展开，工具栏不再提供单侧筛选按钮。组内按拓扑顺序显示，不重复侧徽标；独有提交为 0 的组不显示。两端指向同一个提交且无文件差异时，提示两端没有差异。不同 OID 的提交不因补丁相同而合并。若没有共同历史，明确提示，不画虚构汇合线；浅克隆只覆盖本地可见历史。列表末尾不再重复说明共同历史被排除。
- 普通历史和比较共用一组文件标签、一套选中样式及一个文件面板。普通历史仅显示并选中 `Commit Files`；比较模式额外显示 `File Diff`，进入时默认选中该页，直接比较 **A tip 与 B tip 两个文件树**，而非独有提交文件之和，也不从 merge-base 算起；此页不显示「提交详情」。选择提交后切到 `Commit Files`，仅在此页单选真实提交时显示详情。手动切页不改变已选提交。
- 折叠不会重查已加载的提交或改变 `File Diff`。折叠的提交从选集中移除；范围选择与全选仅覆盖展开且已加载的提交。文本筛选仍查询两侧，折叠状态不影响匹配；未筛选时，已知有独有提交但尚未分页加载的分支也可显示标题。刷新保留折叠状态，交换时折叠状态随原分支移动。外部操作移动了引用时，保留原 OID 并标记「引用已更新」，点「刷新」取新快照。新比较默认展开两侧；退出后恢复此前的历史范围。

### 与工作树比较

- 从任意分支选择「与工作树比较」，进入同一分支比较界面，初始目标为 `Working Tree`。以当前 `HEAD` 为目标的提交端点；如果有本地变动，在 `Working Tree` 所在侧的组内最上方插入一条特殊提交，计数也增加 1。不检出、不联网。
- 特殊提交没有真实 OID、作者或时间，仅用于查看变动文件。它不提供复制哈希、Cherry-Pick、Revert、Reset、改写或创建分支／标签等提交操作。
- `File Diff` 比较所选分支快照和工作树文件，可交换两端；选中特殊提交后，`Commit Files` 始终显示 `HEAD → Working Tree` 的净差异。已保存的暂存、未暂存和未被忽略的未跟踪变动都纳入比较，不叠加同一个文件的多份状态；未保存的编辑器缓冲区不参与比较。
- 双击文件打开只读原生 Diff；工作树侧使用打开时的磁盘内容，只读工作树内的普通文件，不跟随符号链接或 junction。顶部刷新重新读取实际 `HEAD` 及文件差异；退出后恢复此前的历史范围。

## 5. 技术方案

### 承载与模块边界

- **工作台适配**：通过 `contributes.views.scm` 注册 `Branches` TreeView，菜单和节点状态用 `contextValue` 区分；底栏由一个 `WebviewView` 维护分栏与选中。提交与文件行用 `data-vscode-context` 传入目标和状态，通过 `webview/context` 声明原生菜单，只在这些行抑制默认剪切／复制／粘贴。菜单可见性兼容工作台使用的 `webview`／`webviewId` 两种上下文键，并限制在本扩展的历史行内。宿主不以菜单置灰状态代替执行校验。不改 VS Code 内部 DOM，不绑定私有视图命令。
- **图标**：TreeView 和历史范围 Quick Pick 使用 `ThemeIcon`。Webview 不继承工作台字体，从 `vscode.env.appRoot` 下的工作台字体路径读取 VS Code 自带 Codicon，找不到时尝试读取内置 Simple Browser 样式中的同源字体。只将字体数据随 HTML 传入，Webview 用二进制 `FontFace` 加载，不发起字体 URL 请求，不开放安装目录，也不打包字体或 SVG。找不到字体或字体无法解析时，刷新退回文字，引用使用系统符号，警告保留 `!`，原有说明浮层不变。
- **共用界面规则**：`src/views/refPresentation.js` 为分支树和引用选择器提供相同的分组顺序、引用排序和图标；各入口仍决定哪些引用可选、如何显示跟踪信息。`media/historyRows.js` 由宿主和 Webview 共用，保证对比列表的分组顺序、折叠状态与范围选择／全选一致。普通历史和比较共用文件标签、列表／树渲染与选中态；宿主回传选区时只更新界面，不发回选择请求。
- **本地化**：清单中的标题、命令和描述通过 `%key%` 引用 `package.nls*.json`。扩展激活时按 `vscode.env.language` 使用同一套资源，默认英文；历史面板只接收当前语言的所需文案。文案不参与分支选择或 Git 参数判断，Git 子进程的输出语言保持不变。新增可见文案时同时更新三份资源，静态检查校验词条及占位符是否一致。
- **仓库注册与刷新**：使用内置 Git 扩展的 `getAPI(1)` 获取已打开仓库、Git 可执行路径与状态事件。以 worktree 根 URI（包含环境和路径）为显示仓库标识；共享 Git 目录的 worktree 共用本扩展的写队列。只刷新受影响仓库，原生 Changes 仍由内置 Git 独立刷新。
- **Git 服务**：分为引用、历史、对象读取和写操作。Git 在对应仓库工作目录和扩展宿主运行，参数数组执行，不经 shell。使用 `for-each-ref` 获取完整 ref、tip、上游和符号目标，读取仓库快照时同批读取本地分支的 `upstream:track`，不为每条分支启动单独的 Git 进程。用 `status --porcelain=v2 -z` 与 `diff-tree --raw -z` 读取机器可解析的状态和路径。不以显示名或短哈希作为操作标识，支持 SHA-1 和 SHA-256 格式的完整 OID，不按空格切文件名。
- **历史与 Diff**：引用、提交和文件记录绑定仓库、完整 OID 及文件状态。比较面板用 `git log --topo-order --left-right A...B` 统一分页，折叠只影响可见性和选集。各侧独立分配泳道，不跨组连线。`rev-list --left-right --count` 独立统计 `A...B`，用于在分页时识别尚未加载的组；文本筛选复用已固定端点的分支文件差异。工作树比较用 `git diff <oid>` 和 `git ls-files --others --exclude-standard`；宿主只接受从 Git 输出签发的文件标识，读取磁盘时校验路径、文件类型和已打开文件身份。通过只读 `TextDocumentContentProvider` 和 `vscode.diff` 展示两端。根提交以明确的空树语义表示；历史查询禁用隐式获取缺失对象。只打开不超过 1 MiB 且不含 NUL 的 UTF-8 文本。
- **写操作**：按 Git 公共目录排队，执行前复核，结束后刷新。快进和远程整合只获取指定源，临时引用固定本次获取的 OID，整合结束后清理；关闭自动跟随标签、prune 和递归获取子模块。当前分支快进使用 `merge --ff-only`，后台更新使用指向当前本地仓库的非强制 fetch，让 Git 同时检查快进和 worktree 占用。按需保存已跟踪改动，按具名 Stash 的 OID 恢复，不用 `stash@{0}`。合并与检出禁用覆盖忽略文件，变基先检查工作树和重放路径，不自动改动其他分支。
- **提交与文件写入**：`src/git/historyActions.js` 执行提交级操作并复核已知远程历史、当前分支和工作区；较早的消息改写、Squash 和 Drop 通过目标替换及后续提交重放完成，禁用自动更新其他引用。`src/git/selectedChanges.js` 从宿主签发的文件端点生成两个临时树，用 Git 生成补丁，先整批 `git apply --check`，再仅应用于工作树。`src/git/worktreePaths.js` 校验真实文件与路径，不跟随符号链接、junction 或进入嵌套仓库。
- **远程写入**：推送使用固定源 OID 和单个目标 ref，不依赖 `push.default`。删除只发送一个 `:refs/heads/...`，用带明确期望 OID 的 lease 拒绝删除已变化的分支；不发送无条件 `--force`。两者均关闭跟随标签和递归推送子模块，接受 Git 与服务器规则。扩展内的写队列不能约束终端与其他扩展，不承诺跨进程原子性。

### 分页、状态与安全

- 历史查询以 `repoId + 模式 + 解析后的起点 OID + generation` 标识。每次首屏约 120 行，滚动追加并虚拟渲染；保存跨页待连接父 OID 和泳道状态。分页固定起点，引用更新后重建查询，防止跨页错线或重复。提交详情和变更按需加载，按仓库及完整 OID 做有界缓存，不为每个提交预先启动一次 Git。
- 提交选集变化增加独立的 `selectionRevision`。换仓库、切模式、刷新或连续多选时取消旧读请求；宿主和视图都核验作用域，晚到的结果不得覆盖新界面。右键动作还验证仓库、查询 `generation`、选集版本及 HEAD；文件操作只接受当前文件区的宿主签发标识，批量应用还对比选中的文件。底栏隐藏时暂停读取，重新显示时恢复上下文或重发查询。仅持久化仓库选择、标签开关、文件布局与提交列等偏好，不持久化 Git 内容或凭据。
- 不可信工作区或不可用的虚拟文件系统中不运行 Git；缺少 Git、没有仓库、空仓库、缺对象、取消与失败均有独立状态。Webview 使用本地资源和严格 CSP，提交文本和路径只作为文本显示；消息通过类型、仓库及 OID 校验，不开放任意终端命令、路径读取或脚本执行接口。日志隐藏凭据与敏感 URL，不上报仓库内容。

- **IDEA 合并提交差异**：[`VcsLogAsyncChangesTreeModel`](https://github.com/JetBrains/intellij-community/blob/2fbdaf4fb33a750436d9618c7afe830b983050a6/platform/vcs-log/impl/src/com/intellij/vcs/log/ui/frame/VcsLogAsyncChangesTreeModel.kt) 的 `Show Changes from Parents` 将按父提交的完整差异追加在合并后的 `changes` 下方；本扩展默认显示折叠组。标题遵循 [`VcsLogChangesTreeComponents`](https://github.com/JetBrains/intellij-community/blob/2fbdaf4fb33a750436d9618c7afe830b983050a6/platform/vcs-log/impl/src/com/intellij/vcs/log/ui/frame/VcsLogChangesTreeComponents.kt)，用父提交短哈希和标题，不依赖分支名。[`VcsChangesLazilyParsedDetails.getMergedStatusInfo`](https://github.com/JetBrains/intellij-community/blob/2fbdaf4fb33a750436d9618c7afe830b983050a6/platform/vcs-log/impl/src/com/intellij/vcs/log/impl/VcsChangesLazilyParsedDetails.java) 取所有父侧变更的交集。本扩展复用逐父 `git diff-tree` 的读取结果，按字节级路径取交集，保留第一父侧作为顶部两方 Diff 的左侧，不重演合并或解析提交消息里的冲突列表。
- **IDEA 分支更新**：[`GitBranchActionsUtil.updateBranches`](https://github.com/JetBrains/intellij-community/blob/2fbdaf4fb33a750436d9618c7afe830b983050a6/plugins/git4idea/backend/src/ui/branch/GitBranchActionsUtil.kt) 区分当前分支的更新流程和未检出分支的 `remote:local` fetch。这里也区分这两种路径，但统一限制为快进，不自动更新另一个工作树的 checkout。
